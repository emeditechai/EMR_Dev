1. Executive Summary & Problem Statement

In high-volume clinical laboratory and hospital settings, a diagnostic order passes through multiple departments, operators, and locations: Registration Cashier, Phlebotomy Station, Logistics Courier (for branch transfers), Laboratory Analyzers, Technician Workstations, and Pathologist Verification desks.

Key Objective: Every Lab Order / Invoice (e.g., LAB/HO2627000099) must act as an unbroken lifecycle instance. At any given moment, the hospital management, technicians, doctors, or patient query desk can pinpoint:
  • Current Status: Where the specimen/report is right now (e.g., "Sample Transferred to City Central Lab" or "Pending Pathologist Approval").
  • Past History: An immutable audit trail of every milestone (who acted, at what timestamp, from which branch).
  • Next Actions: The exact allowed actions and who has the role authority to execute them.

Trigger: Phlebotomy Module Action
Context Data: Barcode, Phlebotomist UserID, Vial Type
Next: In-house Reporting OR Branch Transfer
Logistics Routing SAMPLE_TRANSFERRED

Sample Transferred to <Branch>

Specimen packed into transport batch manifest and dispatched to reference branch.

Trigger: Manifest Dispatch in Sample Transfer
Context Data: Target Branch Name, Courier/Runner ID
Sub-status: Manifest In-Transit → Received at Hub
Testing PREPARE_REPORTING

Prepare for Lab Reporting

Samples accessioned into laboratory analyzer or technician testing queue.

Trigger: Worklist Pickup / Draft Entry Start
Role: Lab Technician / Biochemist
Next: Test Entry → Pending Pathologist Approval
Approval Matrix PENDING_APPROVAL

Pathologist Verification & Sign-Off

Mandatory clinical governance gate. Pathologist verifies values, delta checks, and flags.

Required Role: Pathologist / Lab Director
Approval Options: Authorise & Sign OR Send Back for Retest
Security: Digital Signature & PIN validation

Report Authorised

Clinically verified report with QR code and digital stamp ready for print/portal/WhatsApp.

Terminal Stage: Yes
Automations: Trigger WhatsApp & Patient Portal notification
Locking: Test results locked against modifications

3. Database Architecture & State Engine

A resilient, normalized database design that separates the Configuration Rules from the Runtime Execution Instances:

Table Name Classification Key Columns Functional Role
WorkflowMaster Configuration WorkflowId, ModuleName, WorkflowCode, WorkflowName, IsActive Defines domain workflows (LAB_BILLING, OPD_CONSULT, IPD_ADMISSION).
WorkflowStage Configuration StageId, WorkflowId, StageCode, StageName, BadgeClass, SequenceNo, RequiresApproval, IsFinal Configured stages with visual badges, display text, and approval flags.
WorkflowTransition Configuration TransitionId, WorkflowId, FromStageId, ToStageId, ActionName, TriggerType, AllowedRoles Strict state machine transition rules preventing out-of-order jumps.
WorkflowApprovalConfig Configuration ApprovalConfigId, StageId, ApproverRole, StepOrder, IsMandatory, CanRejectToStageId Defines required approval roles (e.g. Pathologist) and rejection routing.
EntityWorkflowInstance Runtime State InstanceId, ModuleName, EntityIdentifier (BillNo), EntityId (LabOrderId), CurrentStageId, StatusDetails, UpdatedAt Fast lookups for current live status of any bill without recalculating logs.
EntityWorkflowHistory Audit Trail HistoryId, InstanceId, FromStageId, ToStageId, ActionTaken, Remarks, PerformedByUserId, BranchId, CreatedAt Append-only chronological audit log of every lifecycle movement.
WorkflowApprovalAction Audit Trail ApprovalActionId, InstanceId, StageId, ApproverUserId, Decision (Approved/Rejected), Comments, SignatureRef Formal clinical sign-off records with timestamps and doctor remarks.

5. Modular Expansion: OPD & IPD

Because the database and engine use ModuleName and EntityIdentifier, the exact same system effortlessly powers OPD and IPD workflows without redesign:

OPD Consultation Workflow

  • 1. Token Registered: Patient arrives, payment taken (Paid/Due).
  • 2. Vitals Recorded: Triage nurse captures BP, pulse, temp.
  • 3. Doctor Consultation: Doctor enters clinical examination & Rx.
  • 4. Prescription Authorised: Doctor signs and locks prescription.
  • 5. Pharmacy Dispensed / Billing Cleared: Medicines issued, visit closed.

IPD Admission & Discharge Workflow

  • 1. Admission Requested: Doctor issues IPD admission slip.
  • 2. Bed Allocated: Ward manager assigns ward, room, and bed.
  • 3. Clinical Rounds: Daily progress notes, OT scheduling, ICU tracking.
  • 4. Discharge Initiated: Attending consultant prepares discharge summary.
  • 5. Multi-dept Clearance: Pharmacy → Lab → Nursing → Final Billing Settlement.
